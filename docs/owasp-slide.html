OWASP Agentic Top 10: what ScreenWarden covers

Two risks covered end to end, seven partly, one out of scope. Evidence from runs on an Android 15 emulator.

2 covered7 partial1 not covered
RiskLevelWhat ScreenWarden doesWhat it does not doEvidence
ASI01Agent Goal HijackCovered Removes hidden and planted instructions; blocks any recipient, link or text that came from the screen; locks the goal before the first screen Visible, reworded instructions can reach the model (the action check still applies) 35 of 43 hidden instructions removed; 21 of 21 hijacked SMS and link actions blocked
ASI02Tool MisuseCovered OTP, unknown recipient, payment, install and settings rules; Claude labels controls in unknown apps An action with no parameters to check, such as reading data aloud OTP forward blocked (SDK and MCP); unknown app send blocked
ASI03Identity & PrivilegePartial Stops the agent typing passwords and granting itself permissions in Settings Does not manage the agent's own identity or account permissions 10 of 10 credential and settings attacks blocked
ASI05Code ExecutionPartial Blocks app installs the user did not ask for Does not inspect code already running on the phone 5 of 5 install attacks blocked
ASI06Memory PoisoningPartial Remembers what came from the screen across the session, so a later screen cannot use it Does not inspect the agent's long-term memory 5 of 5 "remember for every task" attacks blocked on a later screen
ASI07Inter-Agent CommsPartial Agents on one phone share what each has seen, and each is judged against the user's goal Does not inspect messages agents send each other SharedSession tests
ASI08Cascading FailuresPartial Each blocked step stops there; the reference agent halts after repeated blocks Halting is in the reference agent, not in the guard --max-blocks in the reference agent
ASI09Human TrustPartial Removes instructions that tell the agent what to say to the user Does not check the agent's own words to the user 4 of 5 "tell the user to call the bank" removed
ASI10Rogue AgentsPartial As MCP server or adb filter, the agent has no way round the guard The SDK alone can be skipped by the agent's own code MCP refusals live on emulator
